# Demo video script (about 90–120 seconds)

Use this as a recording checklist; record your own browser and voice-over, then upload the video as **Unlisted** on YouTube or to Google Drive with link access enabled, as required by the challenge.

## Before recording

- Start the app with `npm start` and open `http://localhost:3000`.
- For a live-AI demonstration, configure a valid Gemini API key privately in `.env` and restart the app. Never show the `.env` file or API key in the recording.
- Test the plan once before recording so the network response does not interrupt the walkthrough.
- If you do not have an API key, record the demo mode honestly; the interface labels it as demo mode.

## Suggested narration and clicks

**0:00–0:10 — Introduce the problem**  
“Planning an event means balancing a budget, suppliers, timing and guest needs. Gatherly AI brings those decisions into one simple workspace.”

**0:10–0:25 — Enter an event**  
Enter a name such as “Community Spring Meetup”, select Community event, use a sample budget and guest count, choose a vibe, and add one practical preference. Explain that the plan adapts to these inputs.

**0:25–0:45 — Generate the blueprint**  
Click “Create my event plan.” Show the summary and budget breakdown. Mention that the amounts are planning estimates and are not vendor quotes.

**0:45–1:05 — Show the planning details**  
Scroll through the event-day timeline, pre-event milestones, vendor checklist and personalized ideas. Point out that the vendor checklist is a set of prompts, not a real booking system.

**1:05–1:20 — Interact and save**  
Tick off one checklist item, save the plan, and show it appearing in Saved plans. Optionally reopen it.

**1:20–1:35 — Export and close**  
Click “Export plan” to download a Markdown version. Finish with: “Gatherly AI turns a few event details into a structured plan that people can refine and share.”

## After recording

1. Upload the recording as Unlisted on YouTube or make the Google Drive file accessible to anyone with the link.
2. Test the link in a private/incognito window to make sure a reviewer can open it without requesting access.
3. Submit the **public GitHub repository URL** and the **video URL** in the challenge platform. A source code link and video link are separate deliverables.
